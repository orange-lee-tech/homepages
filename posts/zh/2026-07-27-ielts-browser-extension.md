## 项目速览

| 指标 | 结果 |
| --- | --- |
| 人类精力投入 | 约 2 小时，主要用于判断、取舍与验收 |

2026 年 7 月下旬，在准备 9 月 23 日雅思机考的过程中，我完成了 IELTS Learning Assistant 的第一版。

它不是一个新的刷题平台，而是一个独立的浏览器侧栏插件：在同桌英语、雅思哥或普通英文网页上，把一次性的练习痕迹沉淀为自己的词汇、原句、错因、标签和复盘资料。

最终产物也许只是一件精美的玩具，但它完成了从真实痛点、产品抽象、技术实现，到构建、分享、维护和商业化想象的闭环。

## 01｜它从一个很小的“不顺手”开始

我先连续使用了几天同桌英语机考平台。它的题库、播放器和机考还原度都不错，但进入精听页面后，我很快遇到一个反复出现的问题：漏听的词、没反应过来的句子、连读和弱读原因，无法直接在学习现场记录下来。

我又下载了雅思哥，希望找到更好的笔记与错题复盘功能。结果发现，两类平台的核心逻辑都更接近“做题与看解析”，而不是“建立个人知识库”。它们能告诉我哪一道题错了，却很难长期回答：

- 我为什么错？
- 这个表达在哪些题里出现过？
- 以后应该怎样复习？
- 能否保留原句和网页来源，而不是只记一个孤立单词？

问题于是从“哪个雅思软件有笔记功能”，变成了：

> 能不能在所有学习网页之上，加一层属于自己的知识管理？

这一步看似只是换了一个问法，实际上已经从“挑选工具”进入了“定义产品”。我不再试图寻找一个完美平台，而是把现有平台继续用于练习，把笔记、错因、标签和复盘交给一个独立插件。

## 02｜我们最终做出了什么

IELTS Learning Assistant 的定位非常克制：**本地优先、浏览器侧栏、专注捕获与复盘**。

它不替代同桌英语，也不和雅思哥竞争；它只负责把用户在网页中的一次性学习行为，变成可编辑、可分类、可检索、可导出的个人资料。

| 能力 | 具体表现 |
| --- | --- |
| 网页捕获 | 打开侧栏，捕获普通网页中选中的英文文本 |
| 结构化记录 | 保存词汇、语境原句、自由笔记、错因和自定义标签 |
| 剑雅分类 | 可选择剑雅 21 至剑雅 4，并按题库年份整理 Library |
| 来源关联 | 持续关联原句和原网页链接，避免脱离语境 |
| 编辑与管理 | 支持再次编辑、保存、复制或删除单条记录 |
| 导出与备份 | 支持复制全部记录，或导出 UTF-8 Markdown |
| 多浏览器构建 | 同一套源码构建 Chrome、Edge 和 Firefox |
| 数据兼容 | 继续读取旧版 `ieltsNotes`，旧记录可补充字段后重新归类 |

插件运行时不连接 AI 服务、远程服务器或 GitHub，也不依赖 VPN。所有学习记录保存在浏览器扩展本地存储中。

这个选择并不“高级”，却让第一版的边界非常清楚：零服务器成本、隐私路径简单、安装后即可长期使用。

> 小项目最容易犯的错误，不是功能太少，而是第一版就急着加入账号、云同步、AI、会员与后台，最后什么都做不稳。

第一版先把“捕获—整理—复盘—备份”做完整。

## 03｜它像一件精美的玩具，但不是空壳

我愿意把这个插件称作“一件精美的玩具”。

它没有复杂账号系统，没有云端数据库，没有真正的 AI Tutor，也没有庞大的用户量。它解决的只是一个非常具体的问题：精听和阅读时，把值得留下的内容顺手记下来。

但“玩具”不等于随手拼出的演示。这个项目已经具备一件可交付软件应有的基本闭环：

- **能安装**：开发模式加载后可以在真实浏览器中使用，而不是停留在代码预览；
- **能保存**：数据写入浏览器本地存储，关闭页面后仍然保留；
- **能升级**：旧笔记不会因为字段变化被直接丢弃，而是进入“未分类旧笔记”；
- **能分享**：构建产物可压缩发送，接收者解压后加载即可使用；
- **能维护**：仓库记录了拉取、构建、提交、推送和高风险命令边界；
- **能扩展**：未来可以继续加入搜索、复习算法、AI 分析与跨设备同步。

所谓“产品感”，并不一定来自功能数量。很多时候，它来自边界清楚、交互顺手、数据不会丢、升级不会乱、别人能够安装、未来还能继续修改。

表面很轻，内部却已经开始形成工程秩序。

## 04｜从九辰官网的 60 小时，到雅思插件的 2 小时

这不是工作量从 60 小时缩水为 2 小时，而是能力开始复用。

九辰教育官网 V1.0 是前一个里程碑。它大约占用了 60 个“人类小时”，包含业务资料整理、31 个静态页面、案例与师资内容治理、独立域名、HTTPS、ICP备案、公安备案、云服务器、Nginx、搜索引擎基础配置和正式上线验收。那是一次完整的企业级门户交付。

IELTS 插件只占用了约 2 个“人类小时”。两者不能按代码量或复杂度直接比较。真正值得比较的是：在官网项目里被迫学会的需求拆解、范围控制、Git 管理、构建验证、错误排查和交接意识，已经变成了可以被快速调用的能力。

| 维度 | 九辰教育官网 | IELTS Learning Assistant |
| --- | --- | --- |
| 问题来源 | 企业品牌、内容、咨询与合规需求 | 个人备考中的精听笔记与复盘痛点 |
| 人类投入 | 约 60 小时 | 约 2 小时 |
| 工程规模 | 31 个静态页面、云服务器与备案闭环 | 浏览器侧栏、本地存储与三端构建 |
| 主要难点 | 信息架构、公开边界、部署与线上故障 | 产品边界、数据结构、浏览器兼容 |
| 共同方法 | 需求拆解、GitHub、构建、验收、交接 | 需求拆解、GitHub、构建、验收、交接 |
| 能力意义 | 第一次组织 AI 完成真实企业交付 | 第一次把能力迁移为个人产品 |

> 60 小时不是被 2 小时“替代”了。那 60 小时沉淀出的判断力、工程语言和协作方法，恰恰是后面 2 小时能够成立的原因。

## 05｜我与 AI 的协作方式，已经从“聊天”变成“推进项目”

为了避免工程性对话在长上下文中失控，我先结束了前面的讨论，把背景、痛点、功能蓝图、技术路线和开发阶段整理成一份交接信息，再开启新的构建对话。

这个动作看起来很“行政”，却让 AI 从第一轮开始就知道：

- 项目要解决什么；
- 第一版不做什么；
- 哪些数据必须保留；
- 怎样才算完成。

实际推进不是一句“帮我做个插件”，而是一条可验证的链路：

> 明确目标 → 读取现状 → 选择模板 → 限定修改范围 → 运行构建 → 浏览器加载 → 反馈问题 → 修正 → Git 提交 → 编写交接

技术上，项目借用了 WXT、React 和 TypeScript 的现成模板。所谓“从零开始”，并不是拒绝模板、库和框架，也不是每一行代码都必须从空白文本敲出；它指的是此前没有完整做过这类作品，而这一次第一次独立走完需求、结构、取舍、验收和交付。

> 借模板不是减分。真正的问题，是只会复制外壳，却不知道为什么这样设计、哪里应该删、哪里必须改、怎样验证它仍然可靠。

## 06｜即使只有两小时，工程管理仍然是精髓

小项目很容易让人放松警惕：功能不多、代码不长、似乎改坏了也可以重来。但恰恰是在这种项目里，是否拥有工程管理意识最容易看出差别。

1. **范围边界**：第一版只解决捕获、记录、分类、复盘与导出，不急着做 AI Tutor。
2. **数据边界**：学习记录默认保存在浏览器本地，并提供 Markdown 备份出口。
3. **兼容边界**：继续读取旧版 `ieltsNotes`，避免升级直接破坏已有记录。
4. **平台边界**：用同一套源码构建 Chrome、Edge 和 Firefox，减少分叉维护。
5. **变更边界**：以 main、commit 和 diff 为事实，不使用不明原因的 force、hard reset。
6. **验收边界**：通过 TypeScript 检查、三端构建、浏览器加载和真实操作确认完成。

仓库中的维护说明甚至明确列出了不应在原因不明时使用的高风险命令：`git push --force`、`git reset --hard`、`git clean -fd`、`npm audit fix --force`。

它们不是复杂技术，却代表一种重要习惯：不为了“快点恢复正常”而破坏可追踪性。

> 不会工程管理的人，会被 AI 的速度反噬；懂得结构、依赖与验收的人，才能把速度变成真正的进度。

## 07｜从第一个网站，到第一个插件，我真正提升了什么

九辰官网和雅思插件，一个是企业门户，一个是个人学习工具；一个需要服务器、备案和大量内容治理，一个只需要浏览器、本地数据和几张界面。

它们在外观上几乎没有关系，但在能力路径上却是连续的：

- **从表达需求，到定义问题**：不只告诉 AI “做什么”，还要明确为什么做、谁使用、什么不做；
- **从生成代码，到组织交付**：关注仓库、分支、构建、产物、安装与交接，而不只关注聊天回复；
- **从解决任务，到抽象产品**：把个人精听痛点抽象成可跨网站使用的浏览器学习层；
- **从一次项目，到能力复用**：把官网项目形成的管理方法迁移到更短、更轻的插件开发；
- **从拿来主义，到吸收再设计**：使用模板与框架，但按真实问题重构字段、流程和产品边界；
- **从完成作品，到看见资产**：开始意识到插件、网站和 App 也可以成为可传播、可维护的互联网资产。

真正的“从零”，是过去没有走过这条路，而现在第一次把完整的方法链条建立起来，并知道下一次可以怎样更快、更稳地再走一遍。

## 08｜我也顺便瞥了一眼商业化潜力

插件完成之后，我自然开始考虑：它是否可以上架 Edge 扩展市场，免费对外开放？免费版和付费版对开发者意味着什么？一个规模很小的工具，怎样从个人需求逐渐形成可持续的互联网资产？

当前版本仍然保持本地优先，没有服务器与 AI 成本，适合作为免费核心工具。未来真正有可能形成付费价值的，并不是把“记笔记”锁起来，而是在用户愿意付费的复杂层上增加服务：

| 层级 | 可能提供的价值 | 现阶段态度 |
| --- | --- | --- |
| 免费核心 | 捕获、笔记、标签、Library、Markdown 导出 | 保持简单、隐私清楚、便于传播 |
| 专业增强 | AI 语音现象分析、同义替换、智能复习与跨设备同步 | 未来探索，不能破坏本地体验 |
| 服务化能力 | 教师工作台、班级资料、团队协作或垂直课程配套 | 需要真实用户与长期验证 |

> 商业化潜力不是给玩具贴上价格标签，而是看它是否持续解决问题、是否拥有清晰边界、是否能够分发、维护和积累用户反馈。

这还不是一份商业计划，只是一次视野变化：以前我把网站和插件看成“完成后就结束的技术作品”；现在开始意识到，它们也可能成为可以持续迭代、公开分发、形成声誉乃至产生收入的数字资产。

## 09｜结语：插件很小，但能力迁移是真实的

回头看，这个项目并不宏大。它没有解决雅思学习的全部问题，也没有证明我已经成为专业插件开发者。

它只是让我在真实使用中发现一个摩擦，把摩擦抽象为产品，再借助 AI、模板、GitHub 和已经形成的工程习惯，把它变成了可以安装和使用的第一件浏览器作品。

九辰官网让我第一次理解：网站上线只是表面，真正上线的是一种组织 AI 完成复杂项目的能力。IELTS Learning Assistant 则进一步证明，这种能力并没有被锁在原项目里，它可以迁移到新的领域，压缩新的试错成本，并开始产生产品意识。

> 不是 AI 用两小时替我做了一个插件，而是我用前一个项目训练出的判断力和工程管理能力，在两小时里组织 AI 完成了一个更轻、更快、更接近产品的闭环。

未来还会有第二个插件、第二个网站，也可能会有真正对外运营的 App。重要的不是每一件作品都足够大，而是这些作品开始连接起来：学习提高判断力，判断力提高工具效率，工具效率释放新的实践空间，新的实践又反过来提升能力。
