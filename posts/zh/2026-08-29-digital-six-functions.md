<p class="post-lede">这是一份关于企业数字化组织形态的阶段性研究记录：我尝试把网站、APP、小程序、私域工作台、数据中台与 Agent 放进同一套生产关系中讨论，并进一步追问它们如何形成数字资本、组织能力与长期竞争力。</p>

## 执行摘要

**六大数字功能单位不是六套 IT，而是同一企业的六种权力：网站管公开身份，APP 管长期关系，小程序管平台交易，私域工作台管人机协同，数据中台管统一事实与参谋，Agent 管意图与执行。未来十年真正的竞争，不是谁拥有最多软件，而是谁能让六者共享同一数据、规则、客户关系与权限，把每次触达变成可重复、可审计、可扩张的现金流。**

这份判断是在此前两份研究已经形成的“数字身体”“One Core, Multiple Interfaces”以及“机器可调用企业”框架上继续推进：此前被放在“后台基础设施”中的**企业私域工作台**与**数据中台**，现在有理由升格为与网站、APP、小程序、Agent 并列的企业一级数字职能。

宏观趋势也支持这种升级。WIPO 最新统计显示，其覆盖约全球 57% GDP 的 29 个经济体，2025 年无形资产投资首次超过 **10 万亿美元**；2008—2025 年实际复合增速约 3.5%，约为有形投资的 3.6 倍。软件、数据、品牌、组织资本等正在从“辅助经营的费用”变成越来越重要的生产资本。

## 六大职能究竟各管什么

理解六者最简单的方法，不是问“它是什么软件”，而是问：

> **企业把哪一种权力交给了它？**

这样一来，六者之间的边界会突然清晰。

| 数字职能 | 一句话本质 | 它掌握的企业权力 | 董事会最该看的 KPI | 典型技术 / 接口 | 战略优先级 |
|---|---|---|---|---|---|
| **网站** | 企业在开放互联网中的“数字国门与公报馆” | 身份权、公开解释权、开放发现权 | 有效自然/AI 流量、线索转化、品牌搜索、机器可读覆盖率、直接收入 | 域名、DNS、HTTPS、CMS、结构化数据、搜索抓取、公开 API | **P0：几乎所有企业都应拥有** |
| **APP** | 企业给高价值客户开的“私人营业厅” | 驻留权、长期关系权、深度服务权 | 30/90/180 日留存、LTV/CAC、交易频率、活跃实名用户、单用户贡献毛利 | iOS/Android、推送、支付、生物识别、摄像头/定位/蓝牙、Deep Link | **P1：高频、高 LTV 企业优先** |
| **小程序** | 超级平台里的“商业领地与快速办事处” | 平台分发权、场景触达权、低摩擦交易权 | 打开→完成率、GMV、会员绑定、复购、服务完成成本、平台依赖度 | 微信登录、支付、扫码、分享、搜索、平台 API、CRM 绑定 | **P0/P1：中国消费与服务业极重要** |
| **企业私域工作台** | 企业自己的“总办事厅与客户接待大厅” | 组织协同权、客户承接权、人机共同作业权 | 流程周期、首次响应、一次解决率、交接损失、客户归属率、人均完成任务数 | 企业微信/协同平台、CRM、SSO/IAM、IM、Contact Center、Workflow、知识库 | **P0：有组织就需要** |
| **数据中台** | 企业的“总参谋部与经营事实中心” | 度量权、记忆权、分析权、决策依据权 | 数据质量、新鲜度、指标一致率、对账差异、分析时延、数据复用率 | 数仓/Lakehouse、ETL/CDC、主数据、Catalog、Lineage、语义层、BI | **P0：六者共同底座** |
| **Agent** | 受制度约束的“高级总督” | 意图理解权、调度权、有限执行权 | 任务成功率、人工接管率、调用成功率、单位任务成本、周期缩短、错误损失、贡献毛利 | 模型、RAG、Memory、API/Tools、MCP、Skills、Evals、Tracing、Policy/Approval | **P1：基础打通后迅速升级** |

这里的“P0/P1”是**投资次序，而不是重要性排名**。例如 APP 的战略价值很高，但一个一年只与客户交互两次的企业没有必要为了“数字化完整”强迫客户安装 APP；相反，官网、企业身份、统一数据和内部工作台几乎没有这种业务频率限制。

**网站——不是仓库本身，而是仓库的权威总目录。**  
此前提出“网站正在成为数字资本的仓库总站”，方向非常接近本质，但要补一个重要边界：客户隐私、订单、库存、账务当然不应该真正堆在公开网站里。更准确的说法是，网站成为企业数字资本对外的**权威投影与总目录**。尤其在 AI 搜索出现后，公开网站同时开始面向人和机器。OpenAI 当前明确说明，公开网站可以进入 ChatGPT Search；网站允许 OAI-SearchBot 抓取，有助于内容被发现、摘要和引用，因此官网的“机器可理解性”正在成为新的企业资产。

这意味着未来 `company.com` 不再只是“公司简介”。它应当回答两种访问者：

> 人问：“你是谁、卖什么、靠不靠谱？”  
> 机器问：“你是谁、有什么能力、价格和规则是什么、我应该怎样与你交互？”

**APP——不是“功能最多的软件”，而是企业进入一个客户日常生活的长期驻点。**  
Apple 公布的研究显示，2025 年全球 App Store 生态促成超过 **1.4 万亿美元**的开发者销售与交易，平均每周触达超过 8.5 亿用户、覆盖 175 个国家和地区；前 100 大 App 中已有超过 40 款具有面向消费者的 AI 能力。这更像是在证明 **APP × AI**，而不是“Agent 取代 APP”。

所以 APP 真正适合银行、证券、出行、零售会员、生产现场、医疗健康、长期设备管理等场景：客户价值足够高，使用足够频繁，需要推送、身份、终端硬件或持续个性化。**它出售的不是页面，而是“企业认识这个客户”的感觉。**

**小程序——不是缩水版 APP，而是企业租来的高效率商业土地。**  
截至 2026 年第一季度，微信与 WeChat 合计月活超过 14 亿；腾讯披露微信小程序 2024 年促成交易额约 **8 万亿元人民币**。2025 年小程序生态已覆盖 100 个国家和地区、108 个行业垂类，跨境交易额同比增长超过 70%。

它特别擅长解决：

> “我现在就要办这件事，但我不愿意为这件事安装一个 APP。”

Uber 在微信内为中国用户提供海外叫车的小程序，就是很典型的全球化案例：企业没有要求中国游客另外学习一套数字入口，而是直接进入他们熟悉的微信环境。

因此，小程序的经济意义是**降低分发摩擦**；它的问题也同样明显——土地属于平台。企业应该经营这块领地，却不应该让客户身份、订单事实和经营逻辑只能存在于地主的土地上。

**企业私域工作台——这是过去四职框架中最值得“升格”的第五职。**

它既不是单纯 OA，也不是单纯 CRM。

它真正回答的是：

> **公司的员工、客服、销售、管理者以及未来的 Agent，到底在哪里“上班”？**

企业微信已经体现出这一方向：它既提供企业内部办公，又开放超过 200 个 API 接入企业自己的应用，同时连接微信消息、小程序与支付；腾讯特别强调，客户关系可以沉淀在企业侧，不因为员工离职而流失。

腾讯云 Contact Center 的架构也说明，“客户接待”正在从电话坐席变成统一工作台：电话、在线消息、音视频、客户信息、历史服务和 CRM 可以在一个工作环境中协同，并通过 SDK/API 嵌入企业自己的业务系统。

所以它是企业的**Human Control Plane——人的操作控制面**。

网站、APP、小程序解决“客户在哪里”；私域工作台解决的是：

> **客户进来以后，企业自己在哪里接住他。**

**数据中台——可以叫“总参谋部 + 经营总账”，但不要把它误认为法定财务总账。**

它负责统一企业对现实的认识：

今天卖了多少？

哪个渠道赚钱？

哪个客户属于谁？

库存到底还有多少？

产品名字究竟怎么定义？

客户生命周期价值怎么计算？

一个“销售额”在财务部、运营部、电商部和董事会嘴里是不是同一个数字？

中国工信部披露，截至 2025 年，国内已经发布大数据领域国家标准 37 项、5700 多家企业通过 DCMM 数据管理能力成熟度认定，并明确强调数据“采、存、算、管、用”全生命周期以及企业数据治理、首席数据官等机制。

但这里必须给董事会划一条红线：

> **数据中台可以成为经营意义上的“统一事实中心”，不能随意取代 ERP/财务系统中的法定账本。**

真正改变货币、合同、库存、订单法律状态的，仍应该是受控的核心业务系统。数据中台负责汇总、治理、解释、分析、预测和对账。

**Agent——它不是第四个、第五个或第六个页面，而是第一次出现的“行动型数字职能”。**

中国 2026 年《智能体规范应用与创新发展实施意见》直接把智能体定义为具备**自主感知、记忆、决策、交互与执行**能力的智能系统，并把任务理解、规划、工具使用、多智能体协同、标准协议及安全治理纳入产业方向。

OpenAI 的 Agent 工具体系体现的也是同一结构：模型可以搜索、读取企业资料、调用工具甚至操作计算机，并通过 Agents SDK 编排单 Agent 或多 Agent 工作流。

因此 Agent 的真正价值不是“聊天”。

而是把过去：

> 客户说话 → 员工理解 → 找系统 → 查数据 → 填表 → 转部门 → 等回复 → 再输入 → 执行

逐步压缩为：

> **意图 → 计划 → 调能力 → 执行 → 验证 → 必要时让人确认。**

但它必须是一位**有宪法、有权限边界、有监察系统的高级总督**。中国监管部门已经明确指出，高自主性、高权限会增加隐私泄露、越权操作和行为失控风险。

## 六者如何组成一家公司

六者最重要的关系，不是技术关系，而是**生产关系**。

把企业理解成一个社会生产单位，可以分成四种权力：

**对外入口权**：网站、APP、小程序。  
**内部操作权**：企业私域工作台。  
**认识和度量权**：数据中台。  
**理解、调度和执行权**：Agent。

于是它们不是六个并列的“软件项目”，而是：

> **三个市场前门 + 一个人类总办事厅 + 一个总参谋部 + 一个智能总督。**

其中真正的企业核心仍然是客户关系、产品、订单、合同、库存、资金、业务规则和实体生产能力。ERP、CRM、OMS、MES、WMS、支付系统等并没有消失，只是本报告遵照“六大一级职能”的划分，不把这些底层生产机械再升格成第七、第八个“衙门”。

此前提出的“身体”比喻，到这里可以进一步精确：

| 企业数字身体 | 作用 |
|---|---|
| 网站 | 面孔、身份证、公报馆 |
| APP | 与重要客户长期握着的手 |
| 小程序 | 伸进平台生态的手 |
| 私域工作台 | 企业内部人员共同工作的躯干 |
| 数据中台 | 记忆、感觉与参谋系统 |
| Agent | 高级认知与行动调度 |
| 底层业务系统 | 骨骼、血液、器官本身 |
| 实体企业 | 最终真正生产商品和服务的身体 |

同一个关系也可以用极简流程表示：

~~~mermaid
flowchart TB
    W[网站] --> C((企业经营核心))
    A[APP] --> C
    M[小程序] --> C
    P[私域工作台] <--> C
    C <--> D[数据中台]
    D --> G[Agent]
    G <--> P
    G --> C
~~~

其中有四条原则尤其重要。

**第一，外部入口可以很多，事实只能有一套。**

同一个商品，官网显示 199 元、APP 显示 189 元、小程序显示 209 元、Agent 又从旧知识库里读到 179 元，这不是“全渠道”，而是企业出现了四个互相矛盾的大脑。

因此，网站、APP、小程序、工作台和 Agent 都应该读取同一套商品、价格、库存、客户、订单和权限事实。数据治理和公共能力复用越成熟，企业新增一个渠道的边际成本越低。工信部推动产品主数据、高质量数据集和数据治理标准，正体现这一方向。

**第二，Agent 可以决定“调用什么”，但不能自己发明事实。**

Agent 可以说：

> “根据库存系统，目前长沙仓库有 18 件。”

而不能说：

> “我觉得应该还有 18 件，所以我替库存系统写成 18 件。”

这就是为什么未来成熟企业必须坚持：

> **Agent ≠ System of Record。**  
> **Agent = Policy-Bounded System of Action。**

OpenAI 的工具调用模式本身就是由模型选择工具，再由应用系统执行真实代码和返回结果；中国的智能体治理框架也强调权限管理、行为管控和全生命周期安全。

**第三，私域工作台将成为“人监督机器、机器辅助人”的共同驾驶舱。**

Agent 不应该悬浮在公司之外。

它应该逐渐进入销售工作台、客服工作台、采购工作台、管理工作台：

> 人看到客户 → Agent 自动补充背景 → 数据中台提供事实 → Agent 准备方案 → 人批准关键动作 → 系统执行 → 结果自动回流。

这比单独建设一个“AI 聊天窗口”重要得多。腾讯在 2026 年已经将 WorkBuddy 作为企业级 AI 工作空间推向全球市场，也说明“协同工作台 + Agent”开始出现融合趋势。

**第四，Agent 不会简单消灭前三个入口，它首先消灭的是“为了操作软件而操作软件”。**

阿里巴巴 2026 年的实际产品路径尤其值得观察：Qwen App 已将淘宝、支付宝、飞猪、高德等原有服务组合成统一自然语言入口；随后又接入淘宝、天猫超过 40 亿件商品目录以及订单、物流、售后等能力，使用户可以通过对话完成复杂购物任务。

这就是非常重要的现实验证：

> Agent 没有把淘宝的商品库、订单系统、支付和履约系统“吃掉”。

相反，**正因为这些数字资产已经存在，Agent 才有东西可以调。**

所以未来最可能发生的不是：

> 网站 → APP → 小程序 → Agent

而是：

> **网站 × APP × 小程序 × 工作台 × 数据 × Agent**

并形成一个整体。

## 数字资本如何变成利润和组织能力

企业家最终不应该用“先进不先进”判断这六项投资，而应该问：

> **它有没有改变公司的现金流方程？**

六者分别作用在不同变量上。

**网站主要解决“低成本持续被发现”。**  
优秀官网积累搜索权重、品牌可信度、内容和 AI 可发现性，长期降低边际获客成本。OpenAI 已允许公开网站参与 ChatGPT Search，并允许企业追踪来自 ChatGPT 的推荐流量，因此 AI 流量已经可以进入企业营销归因体系。

**APP主要解决“一个好客户能留下多久”。**  
它应当重点提高客户终身价值、交易频率、留存和高价值服务深度，而不是追求安装量本身。全球 App Store 生态仍然保持庞大交易规模，而且 AI 正被直接嵌入 APP，这说明 APP 的经济生态位仍然十分稳固。

**小程序主要解决“这一次交易能不能少走几步”。**  
扫码、微信身份、支付、社交传播以及免安装，使它天然适合偶发服务、线下场景和即时交易。微信小程序超过 1.1 亿——准确说是 **11 亿**——月活用户规模及其跨境扩展，也证明它正在从中国本土产品演变为服务中国用户全球活动的一种数字接口。

**私域工作台主要解决“企业能否把关系和组织效率掌握在自己手上”。**  
一个销售离职，如果 3000 个客户同时消失，公司实际上并没有形成客户资产；如果客户关系、沟通历史、订单、任务和服务记录都进入企业受控工作台，个人关系才开始转化为企业资本。腾讯对企业微信的产品设计就明确强调客户关系由企业保留。

**数据中台主要解决“老板看到的世界是不是真的”。**

它的利润作用往往最不显眼，却最基础：

降低错价；  
降低库存积压；  
发现亏损客户；  
识别高毛利 SKU；  
减少重复开发；  
缩短经营分析时间；  
提高预算和预测质量；  
让五个数字入口使用同一套事实。

因此，董事会不应该只问数据中台“带来多少直接销售额”，还要问：

> **没有它，我们因为信息不一致、重复开发、错判经营情况付出了多少钱？**

**Agent主要解决“完成一个任务需要多少脑力、多少人、多少时间”。**

已经有现实研究证明生成式 AI 可以在特定工作场景产生明显生产率提升。例如一项针对 5,179 名客服人员的研究发现，AI 辅助使每小时解决问题数平均提高约 14%，对经验较少、技能较低人员的提升更大；但这是一项特定场景研究，不能机械外推到所有企业。

更重要的历史经验是，AI 这样的通用技术不会“买回来立即提高全要素生产率”。NBER 的“生产率 J 曲线”研究指出，真正释放通用技术价值需要企业同时重构流程、软件、组织、人力资本和商业模式，而这些互补投资本身大量属于无形资本。

所以真正的数字化利润，不是：

> “买 AI → 裁员 → 利润增加。”

而更可能是：

> **数字底盘标准化 → 一个员工能调动更多企业能力 → Agent 承担重复协调 → 管理跨度扩大 → 单位任务成本下降 → 同样规模的人服务更多客户和资产。**

这会改变人才结构。

未来企业人数确实可能下降，但企业这个生产单位不会因此消失。更可能发生的是：**“执行一个步骤的人”减少，“拥有一个结果的人”增加。**

传统岗位可能是：

> 网页运营、APP 运营、小程序运营、客服、数据分析、AI 工程师分别完成自己的一小段。

未来更多岗位会变成：

> **客户旅程负责人、业务能力负责人、数据负责人、Agent 流程负责人。**

一个人负责一个完整经营结果，下面调用软件、数据和多个 Agent。

这正是数字资本真正改变组织的地方：它提高的不是单个人敲键盘的速度，而是**一个人的管理半径和生产半径**。NBER 对“数字资本”的企业研究也发现，IT 只有和企业特定的软件、流程、组织知识与人才投资结合起来，才逐渐形成能够预测未来生产率的企业资本。

会计上，则必须坚决区分两张表。

| 法定会计资产负债表 | 企业家的经济资产负债表 |
|---|---|
| 回答“准则允许确认什么” | 回答“什么决定未来现金流” |
| 强调控制、可辨认性、确认、计量 | 强调客户关系、复用、替代成本、利润贡献、战略选择权 |
| 受会计准则严格约束 | 是董事会内部管理工具 |
| 很多自创品牌、客户关系不能直接入账 | 它们可能恰恰是企业最值钱的东西 |
| SaaS 费用不等于无形资产 | SaaS 周围形成的流程、知识和组织能力仍可能有巨大经济价值 |

IFRS IAS 38 明确规定，无形资产需要满足可辨认、控制和未来经济利益等条件；内部生成品牌、客户名单等即使具有经济价值，也不能因此自动确认为资产。

网站也一样：IFRS 的 SIC-32 规定，满足 IAS 38 条件、能够证明未来经济利益的网站开发支出才可能形成无形资产；如果网站主要用于宣传广告，相应支出通常费用化。

云软件更容易产生误区。IFRS 对 SaaS 配置与定制的分析指出，如果供应商控制软件、企业只是获得服务访问权，很多配置支出并不会因为“花了很多钱”就自动成为企业自己的无形资产。

中国财政部自 2024 年起实施《企业数据资源相关会计处理暂行规定》，但同样没有把“数据有价值”等同于“数据自动入表”；数据资源仍须按照企业会计准则的资产确认逻辑处理，内部研发还须区分研究阶段与满足条件的开发阶段。

因此我建议董事会永远保留两本账：

> **一本给会计师：Accounting Asset Register。**  
> **一本给企业家：Strategic Digital Capital Register。**

第二本账才记录：

域名有没有丢；  
客户是不是企业自己的；  
数据是否干净；  
接口能否迁移；  
一个能力有几个渠道复用；  
换掉微信、苹果或某家大模型以后资产还剩多少。

这是判断“数字资产”还是“数字租赁费用”的关键。

## 可验证假说与未来十年

以下不是把趋势包装成确定未来，而是按照孟德尔式“提出假说—给出机制—寻找可反驳证据”的方式推演。支持这些假说的现实基础包括无形资本投资快速增长、中国已把智能体标准协议、工具链、多智能体协作和智能互联网列入产业政策，以及阿里、腾讯、OpenAI 等已经出现的跨系统智能调用方向。

| 可验证假说 | 为什么可能成立 | 到 2030 年前后怎样验证/证伪 |
|---|---|---|
| **界面折旧加快，能力资产升值** | AI 降低做页面成本，但高质量客户、数据、规则、API、流程难复制 | 新建渠道时间持续缩短，而共享 API/数据的复用率和替换成本持续提高；若企业仍主要靠专属前端代码形成壁垒，则假说减弱 |
| **Agent 不会消灭 APP/网站/小程序，而会吃掉其中大量“操作步骤”** | Agent 擅长意图理解和跨工具编排，但确认、品牌、可视比较、支付、身份仍需要界面 | Agent-assisted journey 上升，同时支付/签约/复杂浏览仍回到受控界面；若主流商业完全脱离任何 UI，则假说被证伪 |
| **私域工作台将成为企业的人机共同控制台** | 员工和 Agent 都需要同一客户上下文、权限、知识和任务队列 | 每名员工负责客户/任务数上升，Agent 在工作台中承担更多准备与执行；若 AI 长期仍以独立聊天框存在，则假说失败 |
| **数据中台将从“看报表”转成实时经营参谋** | Agent 行动要求实时、统一、机器可读的数据，而月度 BI 不够 | 经营指标新鲜度从天/月走向分钟/事件级，自动决策占比提高；若 AI 仍主要依赖静态文档，则演化速度低于预期 |
| **Agent 可发现性将成为新的获客权** | AI 正从给链接发展到理解企业、商品、能力并调用工具 | AI 引荐、Agent 调用、机器成交毛利成为可单独归因渠道；若用户长期仍全部自行搜索和点击，则战略重要性下降 |

第五个假说尤其值得董事会从现在开始观察。

本文把 **Agent Discoverability（智能体可发现性）** 定义为：

> **当客户让 AI 解决一个需求时，AI 能否发现你的企业、理解你的产品和能力、相信信息是最新的、选择你，并最终安全完成调用或交易。**

这不是今天已经成熟的行业标准，而是一个**内部战略管理指标**。

OpenAI 已经允许公开网站进入 ChatGPT Search；中国 2026 年智能体政策的专家解读则明确讨论了智能体数字身份、检索发现、能力声明、互联协议等下一代基础能力。这两边事实上正在从不同方向走向同一个问题：**机器怎样找到另一个可信的经济主体并理解它能做什么。**

因此未来 SEO 的问题：

> “人在 Google、百度、微信里能不能找到我？”

会扩展为：

> “AI 能不能找到我？”  
> “AI 能不能理解我？”  
> “AI 能不能调用我？”  
> “AI 为什么选择我而不是竞争对手？”  
> “AI 调完以后能不能验证我确实履约？”

由此可以推演未来十年的三个阶段。

**现在到约 2028 年：六职归一，先偿还数字基础债。**

企业大量部署 Agent，但真正的差距主要来自谁拥有更干净的数据、更完整的客户身份、更稳定的工作台和更好的系统接口。Agent 首先成为员工副驾驶，自动准备资料、查数据、总结、报价、客服分诊、经营分析。中国当前的智能体政策仍然非常强调安全、权限和分类治理，说明这一阶段“人掌握关键确认权”仍将是主流。

**约 2028—2031 年：软件从“页面集合”逐渐变成“能力集合”。**

企业开始不再问：

> “APP 里有没有查库存页面？”

而问：

> “我们有没有一个可靠的 `查询库存能力`，网站、APP、小程序、工作台和 Agent 谁都能调用？”

MCP 等开放协议已经在推动 AI 与外部工具、数据源连接；OpenAI 也已经支持远程 MCP server。方向不是所有 API 都被某个协议取代，而是企业能力越来越需要以**机器能发现和调用**的形式存在。

**约 2031—2036 年：企业开始同时服务 Human Customer 与 Machine Customer。**

消费者可能对自己的 Agent 说：

> “帮我安排下周北京到大阪三天商务旅行，不坐红眼航班，公司标准内，酒店离客户公司两公里以内。”

他的 Agent 可能直接和航空、酒店、支付、报销、企业差旅 Agent 协作。

阿里 2026 年已经让 Qwen 将淘宝、支付宝、飞猪、高德等既有能力编排为一个自然语言操作入口，并开始把这种能力开放给外部伙伴，例如中国东方航空的搜索、购票、选座、值机流程。这还不是完全自主的机器经济，但已经是一条相当清晰的早期路径。

这会使商业关系在 B2C、B2B 之外增加：

> **B2A2C：Business → Agent → Consumer**

以及更进一步：

> **B2A2A2B：Business → Agent → Agent → Business**

这是战略推演，不是确定预测。但中国已经明确前瞻布局多智能体协同、互联协议、智能互联网、数字身份、发现和合规支付，因此企业至少应该按这个可能性保留架构选择权。

## 董事会的建设次序与治理

最危险的建设方式，是董事长下令：

> 官网做一个项目。  
> APP 做一个项目。  
> 微信做一个项目。  
> 办公系统再采购一个。  
> 数据中台再建一个。  
> AI 部门再做一个 Agent。

六个项目全部成功，公司反而可能出现**六个数字国家**。

真正的顺序应该是：

> **先统一企业，后建设六职。**

董事会可以采用下面这套投资次序。

| 阶段 | 董事会要完成的事 | 为什么先做 |
|---|---|---|
| **基础盘点** | 找出域名、客户身份、商品/服务、订单、财务、数据源、工作台、API、平台账号、Agent 的 Owner | 先知道资产属于谁 |
| **统一事实** | 明确客户、商品、订单、价格、库存、财务指标各自的权威来源；数据中台统一口径 | 没有共同事实，六职协同必然失败 |
| **统一内部工作面** | 打通员工身份、CRM、客服、销售、任务、知识；建立私域工作台 | 先让“企业的人”共享同一公司 |
| **整顿三大外部入口** | 网站负责开放发现；APP负责高频关系；小程序负责低摩擦场景，删除无意义的功能复制 | 每个入口只做自己最擅长的工作 |
| **能力接口化** | 把查商品、报价、查库存、预约、下单、物流、售后等关键动作变成共享 API/Tools | Agent 和未来渠道才有能力可调 |
| **Agent 化** | 先读、再准备、再批准执行，最后才有限自主 | 把风险随成熟度逐级释放 |
| **机器可交易化** | 建立机器发现、机器身份、能力目录、权限、审计以及对外 Agent 接口 | 为 2030 年以后保留战略选择权 |

这套次序意味着一个很重要的原则：

> **先把企业变成一个整体，再让 AI 获得行动力。**

否则，一个更聪明的 Agent 只是能够更快地发现公司内部有七套客户编号、五个销售额定义和三个库存数字。

董事会还应该建立一个统一的六职 KPI，而不是让六个团队各自报喜。

推荐最终只保留五个董事会级指标：

| 董事会指标 | 真正回答的问题 |
|---|---|
| **Digital Contribution Profit** | 整个数字体系究竟贡献了多少增量毛利和成本节约？ |
| **Cost per Completed Job** | 客户或员工真正完成一件事的总成本下降了吗？ |
| **Shared Capability Reuse Rate** | 同一个企业能力被多少入口、员工和 Agent 复用？ |
| **Owned Relationship Ratio** | 有多少客户关系、身份和交易事实真正掌握在企业自己手上？ |
| **Risk-adjusted Agent ROI** | Agent 节省/创造的钱，扣掉模型、治理、错误、返工和风险损失以后还剩多少？ |

这样可以避免最常见的数字化笑话：

> 网站部说 PV 增长 30%。  
> APP 部说 MAU 增长 20%。  
> 小程序说 GMV 增长 40%。  
> OA 说日活 90%。  
> 数据部说建了 500 张表。  
> AI 部说调用了一亿 Token。  
>
> **最后 CFO 说：利润没有增长。**

六职不是为了六个 KPI。

它们共同服务的是**企业经济利润**。

Agent 治理则必须坚持“权限随风险上升而递减”。

最实用的四级制度可以是：

| Agent 权限 | 可以做什么 | 建议 |
|---|---|---|
| **只读** | 查公开资料、知识、客户授权信息 | 大规模部署 |
| **准备** | 准备报价、订单、邮件、退款申请、合同草案 | 大规模部署 |
| **受限执行** | 在金额、对象、时间、业务规则内自动执行 | 充分评测后部署 |
| **高风险自主执行** | 大额支付、法律承诺、关键生产控制等 | 极少数场景，原则上保留人工或确定性控制 |

这不是技术保守主义，而是经济学。

假如一个 Agent 每年节省 300 万人工，却有 1% 概率导致一次 5000 万损失，董事会不能因为它“99% 都做对”就认为这是优秀自动化。

中国监管部门已经把智能体的高权限、越权和行为失控明确列为风险；腾讯朱雀实验室的安全研究也指出，当 Agent 接入代码执行、企业知识和工具以后，提示词注入可能从“答错一句话”升级为数据泄漏、业务篡改甚至系统控制。

因此应该坚持：

> **最小权限 + 短期授权 + 读写分离 + 高风险二次确认 + 全链路日志 + 可回滚 + 持续评测。**

全球经营还要再增加一层“法域路由”。

中国企业出海以后，不应该简单把国内 Agent 复制到欧洲。欧盟 AI Act 的多项条款已于 **2026 年 8 月 2 日**进入适用和执法阶段，其中某些交互式 AI 系统需要让用户知道自己正在与 AI 交互，特定 AI 生成/操纵内容还承担透明度要求。

所以全球化数字六职应遵循：

> **一套企业核心，多个市场界面；一套业务事实，多个法域政策。**

中国站、欧洲站、东南亚小程序、全球 APP 可以呈现不同语言、支付、隐私界面和规则，但客户身份映射、产品事实、能力定义、审计原则不能因此重新分裂为若干家公司。

最后，需要从今天开始正式建设 **Agent Discoverability**。

不需要去追逐所谓“AI SEO 玄学”，而是做好五件非常朴素的事情：

**让机器能找到你。** 官网可抓取、身份清晰、公开事实完整。

**让机器能理解你。** 产品、服务、门店、价格、政策、FAQ 使用结构化数据和稳定语义，而不是全部藏在图片、PDF 和营销口号里。

**让机器能调用你。** 报价、查询、预约、下单、售后等核心业务形成受控 API/Tool；MCP 等协议可以成为 Agent 适配层，但不应让某一种 AI 协议取代企业稳定的业务 API。

**让机器有理由信任你。** 数据新鲜、来源权威、结果可验证、身份可信、错误可回滚。

**最后才让机器替客户行动。** 身份、授权、金额、有效期和审计必须完整。

可以给董事会建立一个简单的内部指标：

[
ADI
=
发现率
	imes 理解正确率
	imes 调用成功率
	imes 信任通过率
	imes 交易完成率
]

**ADI（Agent Discoverability Index）不是现有行业标准，而是本文建议企业自行建立的战略指标。**

它最终应该回答一个极其现实的问题：

> **当未来一亿个客户不再亲自搜索，而是让自己的 AI 帮忙选择供应商时，我们这家公司还能不能进入候选名单？**

## 结论与主要参考来源

从人类长期数字化历史看，最容易犯的错误，就是把“发现时间的先后”误认为“物种替代关系”。

我们先发现了网站，于是以为互联网就是网页。

后来发现 APP，于是以为移动互联网要消灭网页。

后来发现小程序，于是以为免安装会消灭 APP。

现在发现 Agent，又有人认为自然语言会消灭所有软件。

更合理的解释是：

> **人类花了三十多年，逐渐发现了一家数字企业应该拥有的不同器官。**

网站告诉世界：

> **“我是谁。”**

APP告诉重要客户：

> **“我认识你。”**

小程序告诉平台里的客户：

> **“这件事现在就可以办。”**

私域工作台告诉员工：

> **“这是我们的客户，这是我们的工作，这是我们共同服务他的地方。”**

数据中台告诉经营者：

> **“事实到底是什么。”**

Agent告诉整个企业：

> **“我理解你想完成什么，我知道应该调动哪些资源。”**

而企业的制度必须再回答 Agent：

> **“你可以做什么、不能做什么、谁来负责。”**

所以这六者之间最深层的战略关系，可以压缩成一句话：

> **网站取得世界的发现权，APP取得客户的长期关系权，小程序取得平台的即时交易权，私域工作台取得企业内部的人机协同权，数据中台取得对经营事实的度量权，Agent取得受约束的调度执行权。**

六权归一之后，企业才真正成为一个**数字生产单位**。

因此未来最优秀的企业，未必拥有最大的 IT 部门，也未必自己训练最大的模型。

它更可能具有另外一种特征：

> **员工更少，却能管理更多客户；界面更少，却能提供更多服务；代码重复更少，却有更多可复用能力；数据更统一，决策更快；Agent 更多，但权限更清晰；平台很多，但企业仍然拥有自己的客户、状态、规则与品牌。**

这就是数字资本和实体资本逐渐“可以相提并论”的真正含义。

并不是软件取代工厂。

而是：

> **实体资本决定企业能够生产什么；数字资本决定这种生产能力能否被发现、被组织、被交易、被复制、被调度和被全球化。**

其中数字组织力，就是今天讨论的这**六大数字职能共同组成的完整身体**。

最值得董事会长期坚持的原则，则可以进一步压缩成四句话：

> **企业状态要自己拥有。**  
> **市场流量可以租用。**  
> **业务能力必须标准化。**  
> **智能执行必须受治理。**

这也正是此前两份研究从“四大器官”继续扩展到今天“数字六部”之后，最重要的战略升级：**企业数字化的终局不是拥有六套软件，而是拥有一个能够同时被人、员工、平台和机器理解、访问、调用并安全交易的完整企业。**
