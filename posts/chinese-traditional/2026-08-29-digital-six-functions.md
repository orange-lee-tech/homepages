<p class="post-lede">這是一份關於企業數字化組織形態的階段性研究記錄：我嘗試把網站、APP、小程序、私域工作台、數據中台與 Agent 放進同一套生產關係中討論，並進一步追問它們如何形成數字資本、組織能力與長期競爭力。</p>

## 執行摘要

**六大數字功能單位不是六套 IT，而是同一企業的六種權力：網站管公開身份，APP 管長期關係，小程序管平台交易，私域工作台管人機協同，數據中台管統一事實與參謀，Agent 管意圖與執行。未來十年真正的競爭，不是誰擁有最多軟件，而是誰能讓六者共享同一數據、規則、客戶關係與權限，把每次觸達變成可重複、可審計、可擴張的現金流。**

這份判斷是在此前兩份研究已經形成的「數字身體」「One Core, Multiple Interfaces」以及「機器可調用企業」框架上繼續推進：此前被放在「後台基礎設施」中的**企業私域工作台**與**數據中台**，現在有理由升格為與網站、APP、小程序、Agent 並列的企業一級數字職能。

宏觀趨勢也支持這種升級。WIPO 最新統計顯示，其覆蓋約全球 57% GDP 的 29 個經濟體，2025 年無形資產投資首次超過 **10 萬億美元**；2008—2025 年實際複合增速約 3.5%，約為有形投資的 3.6 倍。軟件、數據、品牌、組織資本等正在從「輔助經營的費用」變成越來越重要的生產資本。

## 六大職能究竟各管什麼

理解六者最簡單的方法，不是問「它是什麼軟件」，而是問：

> **企業把哪一種權力交給了它？**

這樣一來，六者之間的邊界會突然清晰。

| 數字職能 | 一句話本質 | 它掌握的企業權力 | 董事會最該看的 KPI | 典型技術 / 接口 | 戰略優先級 |
|---|---|---|---|---|---|
| **網站** | 企業在開放互聯網中的「數字國門與公報館」 | 身份權、公開解釋權、開放發現權 | 有效自然/AI 流量、線索轉化、品牌搜索、機器可讀覆蓋率、直接收入 | 域名、DNS、HTTPS、CMS、結構化數據、搜索抓取、公開 API | **P0：幾乎所有企業都應擁有** |
| **APP** | 企業給高價值客戶開的「私人營業廳」 | 駐留權、長期關係權、深度服務權 | 30/90/180 日留存、LTV/CAC、交易頻率、活躍實名用戶、單用戶貢獻毛利 | iOS/Android、推送、支付、生物識別、攝像頭/定位/藍牙、Deep Link | **P1：高頻、高 LTV 企業優先** |
| **小程序** | 超級平台裏的「商業領地與快速辦事處」 | 平台分發權、場景觸達權、低摩擦交易權 | 打開→完成率、GMV、會員綁定、復購、服務完成成本、平台依賴度 | 微信登錄、支付、掃碼、分享、搜索、平台 API、CRM 綁定 | **P0/P1：中國消費與服務業極重要** |
| **企業私域工作台** | 企業自己的「總辦事廳與客戶接待大廳」 | 組織協同權、客戶承接權、人機共同作業權 | 流程週期、首次響應、一次解決率、交接損失、客戶歸屬率、人均完成任務數 | 企業微信/協同平台、CRM、SSO/IAM、IM、Contact Center、Workflow、知識庫 | **P0：有組織就需要** |
| **數據中台** | 企業的「總參謀部與經營事實中心」 | 度量權、記憶權、分析權、決策依據權 | 數據質量、新鮮度、指標一致率、對賬差異、分析時延、數據複用率 | 數倉/Lakehouse、ETL/CDC、主數據、Catalog、Lineage、語義層、BI | **P0：六者共同底座** |
| **Agent** | 受制度約束的「高級總督」 | 意圖理解權、調度權、有限執行權 | 任務成功率、人工接管率、調用成功率、單位任務成本、週期縮短、錯誤損失、貢獻毛利 | 模型、RAG、Memory、API/Tools、MCP、Skills、Evals、Tracing、Policy/Approval | **P1：基礎打通後迅速升級** |

這裏的「P0/P1」是**投資次序，而不是重要性排名**。例如 APP 的戰略價值很高，但一個一年只與客戶交互兩次的企業沒有必要為了「數字化完整」強迫客戶安裝 APP；相反，官網、企業身份、統一數據和內部工作台幾乎沒有這種業務頻率限制。

**網站——不是倉庫本身，而是倉庫的權威總目錄。**  
此前提出「網站正在成為數字資本的倉庫總站」，方向非常接近本質，但要補一個重要邊界：客戶隱私、訂單、庫存、賬務當然不應該真正堆在公開網站裏。更準確的說法是，網站成為企業數字資本對外的**權威投影與總目錄**。尤其在 AI 搜索出現後，公開網站同時開始面向人和機器。OpenAI 當前明確說明，公開網站可以進入 ChatGPT Search；網站允許 OAI-SearchBot 抓取，有助於內容被發現、摘要和引用，因此官網的「機器可理解性」正在成為新的企業資產。

這意味著未來 `company.com` 不再只是「公司簡介」。它應當回答兩種訪問者：

> 人問：「你是誰、賣什麼、靠不靠譜？」  
> 機器問：「你是誰、有什麼能力、價格和規則是什麼、我應該怎樣與你交互？」

**APP——不是「功能最多的軟件」，而是企業進入一個客戶日常生活的長期駐點。**  
Apple 公佈的研究顯示，2025 年全球 App Store 生態促成超過 **1.4 萬億美元**的開發者銷售與交易，平均每週觸達超過 8.5 億用戶、覆蓋 175 個國家和地區；前 100 大 App 中已有超過 40 款具有面向消費者的 AI 能力。這更像是在證明 **APP × AI**，而不是「Agent 取代 APP」。

所以 APP 真正適合銀行、證券、出行、零售會員、生產現場、醫療健康、長期設備管理等場景：客戶價值足夠高，使用足夠頻繁，需要推送、身份、終端硬件或持續個性化。**它出售的不是頁面，而是「企業認識這個客戶」的感覺。**

**小程序——不是縮水版 APP，而是企業租來的高效率商業土地。**  
截至 2026 年第一季度，微信與 WeChat 合計月活超過 14 億；騰訊披露微信小程序 2024 年促成交易額約 **8 萬億元人民幣**。2025 年小程序生態已覆蓋 100 個國家和地區、108 個行業垂類，跨境交易額同比增長超過 70%。

它特別擅長解決：

> 「我現在就要辦這件事，但我不願意為這件事安裝一個 APP。」

Uber 在微信內為中國用戶提供海外叫車的小程序，就是很典型的全球化案例：企業沒有要求中國遊客另外學習一套數字入口，而是直接進入他們熟悉的微信環境。

因此，小程序的經濟意義是**降低分發摩擦**；它的問題也同樣明顯——土地屬於平台。企業應該經營這塊領地，卻不應該讓客戶身份、訂單事實和經營邏輯只能存在於地主的土地上。

**企業私域工作台——這是過去四職框架中最值得「升格」的第五職。**

它既不是單純 OA，也不是單純 CRM。

它真正回答的是：

> **公司的員工、客服、銷售、管理者以及未來的 Agent，到底在哪裏「上班」？**

企業微信已經體現出這一方向：它既提供企業內部辦公，又開放超過 200 個 API 接入企業自己的應用，同時連接微信消息、小程序與支付；騰訊特別強調，客戶關係可以沉澱在企業側，不因為員工離職而流失。

騰訊雲 Contact Center 的架構也說明，「客戶接待」正在從電話坐席變成統一工作台：電話、在線消息、音視頻、客戶信息、歷史服務和 CRM 可以在一個工作環境中協同，並通過 SDK/API 嵌入企業自己的業務系統。

所以它是企業的**Human Control Plane——人的操作控制面**。

網站、APP、小程序解決「客戶在哪裏」；私域工作台解決的是：

> **客戶進來以後，企業自己在哪裏接住他。**

**數據中台——可以叫「總參謀部 + 經營總賬」，但不要把它誤認為法定財務總賬。**

它負責統一企業對現實的認識：

今天賣了多少？

哪個渠道賺錢？

哪個客戶屬於誰？

庫存到底還有多少？

產品名字究竟怎麼定義？

客戶生命週期價值怎麼計算？

一個「銷售額」在財務部、運營部、電商部和董事會嘴裏是不是同一個數字？

中國工信部披露，截至 2025 年，國內已經發布大數據領域國家標準 37 項、5700 多家企業通過 DCMM 數據管理能力成熟度認定，並明確強調數據「採、存、算、管、用」全生命週期以及企業數據治理、首席數據官等機制。

但這裏必須給董事會劃一條紅線：

> **數據中台可以成為經營意義上的「統一事實中心」，不能隨意取代 ERP/財務系統中的法定賬本。**

真正改變貨幣、合同、庫存、訂單法律狀態的，仍應該是受控的核心業務系統。數據中台負責匯總、治理、解釋、分析、預測和對賬。

**Agent——它不是第四個、第五個或第六個頁面，而是第一次出現的「行動型數字職能」。**

中國 2026 年《智能體規範應用與創新發展實施意見》直接把智能體定義為具備**自主感知、記憶、決策、交互與執行**能力的智能系統，並把任務理解、規劃、工具使用、多智能體協同、標準協議及安全治理納入產業方向。

OpenAI 的 Agent 工具體系體現的也是同一結構：模型可以搜索、讀取企業資料、調用工具甚至操作計算機，並通過 Agents SDK 編排單 Agent 或多 Agent 工作流。

因此 Agent 的真正價值不是「聊天」。

而是把過去：

> 客戶說話 → 員工理解 → 找系統 → 查數據 → 填表 → 轉部門 → 等回覆 → 再輸入 → 執行

逐步壓縮為：

> **意圖 → 計劃 → 調能力 → 執行 → 驗證 → 必要時讓人確認。**

但它必須是一位**有憲法、有權限邊界、有監察系統的高級總督**。中國監管部門已經明確指出，高自主性、高權限會增加隱私洩露、越權操作和行為失控風險。

## 六者如何組成一家公司

六者最重要的關係，不是技術關係，而是**生產關係**。

把企業理解成一個社會生產單位，可以分成四種權力：

**對外入口權**：網站、APP、小程序。  
**內部操作權**：企業私域工作台。  
**認識和度量權**：數據中台。  
**理解、調度和執行權**：Agent。

於是它們不是六個並列的「軟件項目」，而是：

> **三個市場前門 + 一個人類總辦事廳 + 一個總參謀部 + 一個智能總督。**

其中真正的企業核心仍然是客戶關係、產品、訂單、合同、庫存、資金、業務規則和實體生產能力。ERP、CRM、OMS、MES、WMS、支付系統等並沒有消失，只是本報告遵照「六大一級職能」的劃分，不把這些底層生產機械再升格成第七、第八個「衙門」。

此前提出的「身體」比喻，到這裏可以進一步精確：

| 企業數字身體 | 作用 |
|---|---|
| 網站 | 面孔、身份證、公報館 |
| APP | 與重要客戶長期握著的手 |
| 小程序 | 伸進平台生態的手 |
| 私域工作台 | 企業內部人員共同工作的軀幹 |
| 數據中台 | 記憶、感覺與參謀系統 |
| Agent | 高級認知與行動調度 |
| 底層業務系統 | 骨骼、血液、器官本身 |
| 實體企業 | 最終真正生產商品和服務的身體 |

同一個關係也可以用極簡流程表示：

~~~mermaid
flowchart TB
    W[網站] --> C((企業經營核心))
    A[APP] --> C
    M[小程序] --> C
    P[私域工作台] <--> C
    C <--> D[數據中台]
    D --> G[Agent]
    G <--> P
    G --> C
~~~

其中有四條原則尤其重要。

**第一，外部入口可以很多，事實只能有一套。**

同一個商品，官網顯示 199 元、APP 顯示 189 元、小程序顯示 209 元、Agent 又從舊知識庫裏讀到 179 元，這不是「全渠道」，而是企業出現了四個互相矛盾的大腦。

因此，網站、APP、小程序、工作台和 Agent 都應該讀取同一套商品、價格、庫存、客戶、訂單和權限事實。數據治理和公共能力複用越成熟，企業新增一個渠道的邊際成本越低。工信部推動產品主數據、高質量數據集和數據治理標準，正體現這一方向。

**第二，Agent 可以決定「調用什麼」，但不能自己發明事實。**

Agent 可以說：

> 「根據庫存系統，目前長沙倉庫有 18 件。」

而不能說：

> 「我覺得應該還有 18 件，所以我替庫存系統寫成 18 件。」

這就是為什麼未來成熟企業必須堅持：

> **Agent ≠ System of Record。**  
> **Agent = Policy-Bounded System of Action。**

OpenAI 的工具調用模式本身就是由模型選擇工具，再由應用系統執行真實代碼和返回結果；中國的智能體治理框架也強調權限管理、行為管控和全生命週期安全。

**第三，私域工作台將成為「人監督機器、機器輔助人」的共同駕駛艙。**

Agent 不應該懸浮在公司之外。

它應該逐漸進入銷售工作台、客服工作台、採購工作台、管理工作台：

> 人看到客戶 → Agent 自動補充背景 → 數據中台提供事實 → Agent 準備方案 → 人批准關鍵動作 → 系統執行 → 結果自動回流。

這比單獨建設一個「AI 聊天窗口」重要得多。騰訊在 2026 年已經將 WorkBuddy 作為企業級 AI 工作空間推向全球市場，也說明「協同工作台 + Agent」開始出現融合趨勢。

**第四，Agent 不會簡單消滅前三個入口，它首先消滅的是「為了操作軟件而操作軟件」。**

阿里巴巴 2026 年的實際產品路徑尤其值得觀察：Qwen App 已將淘寶、支付寶、飛豬、高德等原有服務組合成統一自然語言入口；隨後又接入淘寶、天貓超過 40 億件商品目錄以及訂單、物流、售後等能力，使用戶可以通過對話完成複雜購物任務。

這就是非常重要的現實驗證：

> Agent 沒有把淘寶的商品庫、訂單系統、支付和履約系統「吃掉」。

相反，**正因為這些數字資產已經存在，Agent 才有東西可以調。**

所以未來最可能發生的不是：

> 網站 → APP → 小程序 → Agent

而是：

> **網站 × APP × 小程序 × 工作台 × 數據 × Agent**

並形成一個整體。

## 數字資本如何變成利潤和組織能力

企業家最終不應該用「先進不先進」判斷這六項投資，而應該問：

> **它有沒有改變公司的現金流方程？**

可以把整個數字體系的經濟作用粗略表達為：

[

觸達
	imes 轉化
	imes 客單價

	imes 毛利率

-

]

六者分別作用在不同變量上。

**網站主要解決「低成本持續被發現」。**  
優秀官網積累搜索權重、品牌可信度、內容和 AI 可發現性，長期降低邊際獲客成本。OpenAI 已允許公開網站參與 ChatGPT Search，並允許企業追蹤來自 ChatGPT 的推薦流量，因此 AI 流量已經可以進入企業營銷歸因體系。

**APP 主要解決「一個好客戶能留下多久」。**  
它應當重點提高客戶終身價值、交易頻率、留存和高價值服務深度，而不是追求安裝量本身。全球 App Store 生態仍然保持龐大交易規模，而且 AI 正被直接嵌入 APP，這說明 APP 的經濟生態位仍然十分穩固。

**小程序主要解決「這一次交易能不能少走幾步」。**  
掃碼、微信身份、支付、社交傳播以及免安裝，使它天然適合偶發服務、線下場景和即時交易。微信小程序超過 1.1 億——準確說是 **11 億**——月活用戶規模及其跨境擴展，也證明它正在從中國本土產品演變為服務中國用戶全球活動的一種數字接口。

**私域工作台主要解決「企業能否把關係和組織效率掌握在自己手上」。**  
一個銷售離職，如果 3000 個客戶同時消失，公司實際上並沒有形成客戶資產；如果客戶關係、溝通歷史、訂單、任務和服務記錄都進入企業受控工作台，個人關係才開始轉化為企業資本。騰訊對企業微信的產品設計就明確強調客戶關係由企業保留。

**數據中台主要解決「老闆看到的世界是不是真的」。**

它的利潤作用往往最不顯眼，卻最基礎：

降低錯價；  
降低庫存積壓；  
發現虧損客戶；  
識別高毛利 SKU；  
減少重複開發；  
縮短經營分析時間；  
提高預算和預測質量；  
讓五個數字入口使用同一套事實。

因此，董事會不應該只問數據中台「帶來多少直接銷售額」，還要問：

> **沒有它，我們因為信息不一致、重複開發、錯判經營情況付出了多少錢？**

**Agent 主要解決「完成一個任務需要多少腦力、多少人、多少時間」。**

已經有現實研究證明生成式 AI 可以在特定工作場景產生明顯生產率提升。例如一項針對 5,179 名客服人員的研究發現，AI 輔助使每小時解決問題數平均提高約 14%，對經驗較少、技能較低人員的提升更大；但這是一項特定場景研究，不能機械外推到所有企業。

更重要的歷史經驗是，AI 這樣的通用技術不會「買回來立即提高全要素生產率」。NBER 的「生產率 J 曲線」研究指出，真正釋放通用技術價值需要企業同時重構流程、軟件、組織、人力資本和商業模式，而這些互補投資本身大量屬於無形資本。

所以真正的數字化利潤，不是：

> 「買 AI → 裁員 → 利潤增加。」

而更可能是：

> **數字底盤標準化 → 一個員工能調動更多企業能力 → Agent 承擔重複協調 → 管理跨度擴大 → 單位任務成本下降 → 同樣規模的人服務更多客戶和資產。**

這會改變人才結構。

未來企業人數確實可能下降，但企業這個生產單位不會因此消失。更可能發生的是：**「執行一個步驟的人」減少，「擁有一個結果的人」增加。**

傳統崗位可能是：

> 網頁運營、APP 運營、小程序運營、客服、數據分析、AI 工程師分別完成自己的一小段。

未來更多崗位會變成：

> **客戶旅程負責人、業務能力負責人、數據負責人、Agent 流程負責人。**

一個人負責一個完整經營結果，下面調用軟件、數據和多個 Agent。

這正是數字資本真正改變組織的地方：它提高的不是單個人敲鍵盤的速度，而是**一個人的管理半徑和生產半徑**。NBER 對「數字資本」的企業研究也發現，IT 只有和企業特定的軟件、流程、組織知識與人才投資結合起來，才逐漸形成能夠預測未來生產率的企業資本。

會計上，則必須堅決區分兩張表。

| 法定會計資產負債表 | 企業家的經濟資產負債表 |
|---|---|
| 回答「準則允許確認什麼」 | 回答「什麼決定未來現金流」 |
| 強調控制、可辨認性、確認、計量 | 強調客戶關係、複用、替代成本、利潤貢獻、戰略選擇權 |
| 受會計準則嚴格約束 | 是董事會內部管理工具 |
| 很多自創品牌、客戶關係不能直接入賬 | 它們可能恰恰是企業最值錢的東西 |
| SaaS 費用不等於無形資產 | SaaS 周圍形成的流程、知識和組織能力仍可能有巨大經濟價值 |

IFRS IAS 38 明確規定，無形資產需要滿足可辨認、控制和未來經濟利益等條件；內部生成品牌、客戶名單等即使具有經濟價值，也不能因此自動確認為資產。

網站也一樣：IFRS 的 SIC-32 規定，滿足 IAS 38 條件、能夠證明未來經濟利益的網站開發支出才可能形成無形資產；如果網站主要用於宣傳廣告，相應支出通常費用化。

雲軟件更容易產生誤區。IFRS 對 SaaS 配置與定制的分析指出，如果供應商控制軟件、企業只是獲得服務訪問權，很多配置支出並不會因為「花了很多錢」就自動成為企業自己的無形資產。

中國財政部自 2024 年起實施《企業數據資源相關會計處理暫行規定》，但同樣沒有把「數據有價值」等同於「數據自動入表」；數據資源仍須按照企業會計準則的資產確認邏輯處理，內部研發還須區分研究階段與滿足條件的開發階段。

因此我建議董事會永遠保留兩本賬：

> **一本給會計師：Accounting Asset Register。**  
> **一本給企業家：Strategic Digital Capital Register。**

第二本賬才記錄：

域名有沒有丟；  
客戶是不是企業自己的；  
數據是否乾淨；  
接口能否遷移；  
一個能力有幾個渠道複用；  
換掉微信、蘋果或某家大模型以後資產還剩多少。

這是判斷「數字資產」還是「數字租賃費用」的關鍵。

## 可驗證假說與未來十年

以下不是把趨勢包裝成確定未來，而是按照孟德爾式「提出假說—給出機制—尋找可反駁證據」的方式推演。支持這些假說的現實基礎包括無形資本投資快速增長、中國已把智能體標準協議、工具鏈、多智能體協作和智能互聯網列入產業政策，以及阿里、騰訊、OpenAI 等已經出現的跨系統智能調用方向。

| 可驗證假說 | 為什麼可能成立 | 到 2030 年前後怎樣驗證/證偽 |
|---|---|---|
| **界面折舊加快，能力資產升值** | AI 降低做頁面成本，但高質量客戶、數據、規則、API、流程難複製 | 新建渠道時間持續縮短，而共享 API/數據的複用率和替換成本持續提高；若企業仍主要靠專屬前端代碼形成壁壘，則假說減弱 |
| **Agent 不會消滅 APP/網站/小程序，而會吃掉其中大量「操作步驟」** | Agent 擅長意圖理解和跨工具編排，但確認、品牌、可視比較、支付、身份仍需要界面 | Agent-assisted journey 上升，同時支付/簽約/複雜瀏覽仍回到受控界面；若主流商業完全脫離任何 UI，則假說被證偽 |
| **私域工作台將成為企業的人機共同控制台** | 員工和 Agent 都需要同一客戶上下文、權限、知識和任務隊列 | 每名員工負責客戶/任務數上升，Agent 在工作台中承擔更多準備與執行；若 AI 長期仍以獨立聊天框存在，則假說失敗 |
| **數據中台將從「看報表」轉成實時經營參謀** | Agent 行動要求實時、統一、機器可讀的數據，而月度 BI 不夠 | 經營指標新鮮度從天/月走向分鐘/事件級，自動決策佔比提高；若 AI 仍主要依賴靜態文檔，則演化速度低於預期 |
| **Agent 可發現性將成為新的獲客權** | AI 正從給鏈接發展到理解企業、商品、能力並調用工具 | AI 引薦、Agent 調用、機器成交毛利成為可單獨歸因渠道；若用戶長期仍全部自行搜索和點擊，則戰略重要性下降 |

第五個假說尤其值得董事會從現在開始觀察。

本文把 **Agent Discoverability（智能體可發現性）** 定義為：

> **當客戶讓 AI 解決一個需求時，AI 能否發現你的企業、理解你的產品和能力、相信信息是最新的、選擇你，並最終安全完成調用或交易。**

這不是今天已經成熟的行業標準，而是一個**內部戰略管理指標**。

OpenAI 已經允許公開網站進入 ChatGPT Search；中國 2026 年智能體政策的專家解讀則明確討論了智能體數字身份、檢索發現、能力聲明、互聯協議等下一代基礎能力。這兩邊事實上正在從不同方向走向同一個問題：**機器怎樣找到另一個可信的經濟主體並理解它能做什麼。**

因此未來 SEO 的問題：

> 「人在 Google、百度、微信裏能不能找到我？」

會擴展為：

> 「AI 能不能找到我？」  
> 「AI 能不能理解我？」  
> 「AI 能不能調用我？」  
> 「AI 為什麼選擇我而不是競爭對手？」  
> 「AI 調完以後能不能驗證我確實履約？」

由此可以推演未來十年的三個階段。

**現在到約 2028 年：六職歸一，先償還數字基礎債。**

企業大量部署 Agent，但真正的差距主要來自誰擁有更乾淨的數據、更完整的客戶身份、更穩定的工作台和更好的系統接口。Agent 首先成為員工副駕駛，自動準備資料、查數據、總結、報價、客服分診、經營分析。中國當前的智能體政策仍然非常強調安全、權限和分類治理，說明這一階段「人掌握關鍵確認權」仍將是主流。

**約 2028—2031 年：軟件從「頁面集合」逐漸變成「能力集合」。**

企業開始不再問：

> 「APP 裏有沒有查庫存頁面？」

而問：

> 「我們有沒有一個可靠的 `查詢庫存能力`，網站、APP、小程序、工作台和 Agent 誰都能調用？」

MCP 等開放協議已經在推動 AI 與外部工具、數據源連接；OpenAI 也已經支持遠程 MCP server。方向不是所有 API 都被某個協議取代，而是企業能力越來越需要以**機器能發現和調用**的形式存在。

**約 2031—2036 年：企業開始同時服務 Human Customer 與 Machine Customer。**

消費者可能對自己的 Agent 說：

> 「幫我安排下週北京到大阪三天商務旅行，不坐紅眼航班，公司標準內，酒店離客戶公司兩公里以內。」

他的 Agent 可能直接和航空、酒店、支付、報銷、企業差旅 Agent 協作。

阿里 2026 年已經讓 Qwen 將淘寶、支付寶、飛豬、高德等既有能力編排為一個自然語言操作入口，並開始把這種能力開放給外部夥伴，例如中國東方航空的搜索、購票、選座、值機流程。這還不是完全自主的機器經濟，但已經是一條相當清晰的早期路徑。

這會使商業關係在 B2C、B2B 之外增加：

> **B2A2C：Business → Agent → Consumer**

以及更進一步：

> **B2A2A2B：Business → Agent → Agent → Business**

這是戰略推演，不是確定預測。但中國已經明確前瞻佈局多智能體協同、互聯協議、智能互聯網、數字身份、發現和合規支付，因此企業至少應該按這個可能性保留架構選擇權。

## 董事會的建設次序與治理

最危險的建設方式，是董事長下令：

> 官網做一個項目。  
> APP 做一個項目。  
> 微信做一個項目。  
> 辦公系統再採購一個。  
> 數據中台再建一個。  
> AI 部門再做一個 Agent。

六個項目全部成功，公司反而可能出現**六個數字國家**。

真正的順序應該是：

> **先統一企業，後建設六職。**

董事會可以採用下面這套投資次序。

| 階段 | 董事會要完成的事 | 為什麼先做 |
|---|---|---|
| **基礎盤點** | 找出域名、客戶身份、商品/服務、訂單、財務、數據源、工作台、API、平台賬號、Agent 的 Owner | 先知道資產屬於誰 |
| **統一事實** | 明確客戶、商品、訂單、價格、庫存、財務指標各自的權威來源；數據中台統一口徑 | 沒有共同事實，六職協同必然失敗 |
| **統一內部工作面** | 打通員工身份、CRM、客服、銷售、任務、知識；建立私域工作台 | 先讓「企業的人」共享同一公司 |
| **整頓三大外部入口** | 網站負責開放發現；APP 負責高頻關係；小程序負責低摩擦場景，刪除無意義的功能複製 | 每個入口只做自己最擅長的工作 |
| **能力接口化** | 把查商品、報價、查庫存、預約、下單、物流、售後等關鍵動作變成共享 API/Tools | Agent 和未來渠道才有能力可調 |
| **Agent 化** | 先讀、再準備、再批准執行，最後才有限自主 | 把風險隨成熟度逐級釋放 |
| **機器可交易化** | 建立機器發現、機器身份、能力目錄、權限、審計以及對外 Agent 接口 | 為 2030 年以後保留戰略選擇權 |

這套次序意味著一個很重要的原則：

> **先把企業變成一個整體，再讓 AI 獲得行動力。**

否則，一個更聰明的 Agent 只是能夠更快地發現公司內部有七套客戶編號、五個銷售額定義和三個庫存數字。

董事會還應該建立一個統一的六職 KPI，而不是讓六個團隊各自報喜。

推薦最終只保留五個董事會級指標：

| 董事會指標 | 真正回答的問題 |
|---|---|
| **Digital Contribution Profit** | 整個數字體系究竟貢獻了多少增量毛利和成本節約？ |
| **Cost per Completed Job** | 客戶或員工真正完成一件事的總成本下降了嗎？ |
| **Shared Capability Reuse Rate** | 同一個企業能力被多少入口、員工和 Agent 複用？ |
| **Owned Relationship Ratio** | 有多少客戶關係、身份和交易事實真正掌握在企業自己手上？ |
| **Risk-adjusted Agent ROI** | Agent 節省/創造的錢，扣掉模型、治理、錯誤、返工和風險損失以後還剩多少？ |

這樣可以避免最常見的數字化笑話：

> 網站部說 PV 增長 30%。  
> APP 部說 MAU 增長 20%。  
> 小程序說 GMV 增長 40%。  
> OA 說日活 90%。  
> 數據部說建了 500 張表。  
> AI 部說調用了一億 Token。  
>
> **最後 CFO 說：利潤沒有增長。**

六職不是為了六個 KPI。

它們共同服務的是**企業經濟利潤**。

Agent 治理則必須堅持「權限隨風險上升而遞減」。

最實用的四級制度可以是：

| Agent 權限 | 可以做什麼 | 建議 |
|---|---|---|
| **只讀** | 查公開資料、知識、客戶授權信息 | 大規模部署 |
| **準備** | 準備報價、訂單、郵件、退款申請、合同草案 | 大規模部署 |
| **受限執行** | 在金額、對象、時間、業務規則內自動執行 | 充分評測後部署 |
| **高風險自主執行** | 大額支付、法律承諾、關鍵生產控制等 | 極少數場景，原則上保留人工或確定性控制 |

這不是技術保守主義，而是經濟學。

假如一個 Agent 每年節省 300 萬人工，卻有 1% 概率導致一次 5000 萬損失，董事會不能因為它「99% 都做對」就認為這是優秀自動化。

中國監管部門已經把智能體的高權限、越權和行為失控明確列為風險；騰訊朱雀實驗室的安全研究也指出，當 Agent 接入代碼執行、企業知識和工具以後，提示詞注入可能從「答錯一句話」升級為數據洩漏、業務篡改甚至系統控制。

因此應該堅持：

> **最小權限 + 短期授權 + 讀寫分離 + 高風險二次確認 + 全鏈路日誌 + 可回滾 + 持續評測。**

全球經營還要再增加一層「法域路由」。

中國企業出海以後，不應該簡單把國內 Agent 複製到歐洲。歐盟 AI Act 的多項條款已於 **2026 年 8 月 2 日**進入適用和執法階段，其中某些交互式 AI 系統需要讓用戶知道自己正在與 AI 交互，特定 AI 生成/操縱內容還承擔透明度要求。

所以全球化數字六職應遵循：

> **一套企業核心，多個市場界面；一套業務事實，多個法域政策。**

中國站、歐洲站、東南亞小程序、全球 APP 可以呈現不同語言、支付、隱私界面和規則，但客戶身份映射、產品事實、能力定義、審計原則不能因此重新分裂為若干家公司。

最後，需要從今天開始正式建設 **Agent Discoverability**。

不需要去追逐所謂「AI SEO 玄學」，而是做好五件非常樸素的事情：

**讓機器能找到你。** 官網可抓取、身份清晰、公開事實完整。

**讓機器能理解你。** 產品、服務、門店、價格、政策、FAQ 使用結構化數據和穩定語義，而不是全部藏在圖片、PDF 和營銷口號裏。

**讓機器能調用你。** 報價、查詢、預約、下單、售後等核心業務形成受控 API/Tool；MCP 等協議可以成為 Agent 適配層，但不應讓某一種 AI 協議取代企業穩定的業務 API。

**讓機器有理由信任你。** 數據新鮮、來源權威、結果可驗證、身份可信、錯誤可回滾。

**最後才讓機器替客戶行動。** 身份、授權、金額、有效期和審計必須完整。

可以給董事會建立一個簡單的內部指標：

[
ADI
=
發現率
	imes 理解正確率
	imes 調用成功率
	imes 信任通過率
	imes 交易完成率
]

**ADI（Agent Discoverability Index）不是現有行業標準，而是本文建議企業自行建立的戰略指標。**

它最終應該回答一個極其現實的問題：

> **當未來一億個客戶不再親自搜索，而是讓自己的 AI 幫忙選擇供應商時，我們這家公司還能不能進入候選名單？**

## 結論與主要參考來源

從人類長期數字化歷史看，最容易犯的錯誤，就是把「發現時間的先後」誤認為「物種替代關係」。

我們先發現了網站，於是以為互聯網就是網頁。

後來發現 APP，於是以為移動互聯網要消滅網頁。

後來發現小程序，於是以為免安裝會消滅 APP。

現在發現 Agent，又有人認為自然語言會消滅所有軟件。

更合理的解釋是：

> **人類花了三十多年，逐漸發現了一家數字企業應該擁有的不同器官。**

網站告訴世界：

> **「我是誰。」**

APP 告訴重要客戶：

> **「我認識你。」**

小程序告訴平台裏的客戶：

> **「這件事現在就可以辦。」**

私域工作台告訴員工：

> **「這是我們的客戶，這是我們的工作，這是我們共同服務他的地方。」**

數據中台告訴經營者：

> **「事實到底是什麼。」**

Agent 告訴整個企業：

> **「我理解你想完成什麼，我知道應該調動哪些資源。」**

而企業的制度必須再回答 Agent：

> **「你可以做什麼、不能做什麼、誰來負責。」**

所以這六者之間最深層的戰略關係，可以壓縮成一句話：

> **網站取得世界的發現權，APP 取得客戶的長期關係權，小程序取得平台的即時交易權，私域工作台取得企業內部的人機協同權，數據中台取得對經營事實的度量權，Agent 取得受約束的調度執行權。**

六權歸一之後，企業才真正成為一個**數字生產單位**。

因此未來最優秀的企業，未必擁有最大的 IT 部門，也未必自己訓練最大的模型。

它更可能具有另外一種特徵：

> **員工更少，卻能管理更多客戶；界面更少，卻能提供更多服務；代碼重複更少，卻有更多可複用能力；數據更統一，決策更快；Agent 更多，但權限更清晰；平台很多，但企業仍然擁有自己的客戶、狀態、規則與品牌。**

這就是數字資本和實體資本逐漸「可以相提並論」的真正含義。

並不是軟件取代工廠。

而是：

> **實體資本決定企業能夠生產什麼；數字資本決定這種生產能力能否被發現、被組織、被交易、被複製、被調度和被全球化。**

最終可以把現代企業競爭力寫成一個戰略公式：

[
oxed{
企業長期競爭力
=
實體生產力
	imes
數字組織力
	imes
智能執行力
	imes
治理可信度
}
]

其中數字組織力，就是今天討論的這**六大數字職能共同組成的完整身體**。

最值得董事會長期堅持的原則，則可以進一步壓縮成四句話：

> **企業狀態要自己擁有。**  
> **市場流量可以租用。**  
> **業務能力必須標準化。**  
> **智能執行必須受治理。**

這也正是此前兩份研究從「四大器官」繼續擴展到今天「數字六部」之後，最重要的戰略升級：**企業數字化的終局不是擁有六套軟件，而是擁有一個能夠同時被人、員工、平台和機器理解、訪問、調用並安全交易的完整企業。**
